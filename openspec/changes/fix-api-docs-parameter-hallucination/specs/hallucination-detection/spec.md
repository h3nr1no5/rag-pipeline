# Hallucination Detection

## Purpose

Define assertion-driven hallucination detection with corrective action for the DSPy API documentation pipeline, ensuring that generated responses with invalid citations or missing function references are retried or replaced with a safe fallback.

## ADDED Requirements

### Requirement: Assertion failures SHALL trigger retry with plain Predict

When the ChainOfThought `response_generator` produces an answer that fails `validate_citations()` or `check_question_references()`, the pipeline SHALL retry generation using the plain `Predict` fallback generator before returning content to the user.

#### Scenario: CoT assertion failure triggers Predict retry
- **WHEN** `_generate_with_assertions()` runs the ChainOfThought generator
- **AND** the resulting answer fails one or more assertions
- **THEN** the pipeline SHALL invoke `_generate_fallback()` (plain Predict)
- **AND** SHALL re-run assertions on the Predict output

#### Scenario: CoT exception still falls through to Predict
- **WHEN** the ChainOfThought `response_generator` call raises an exception
- **THEN** the pipeline SHALL invoke `_generate_fallback()` (unchanged from current behavior)

### Requirement: Pipeline SHALL return structured fallback when all retries fail

When both the ChainOfThought and Predict attempts fail assertions, the pipeline SHALL return a structured answer that lists the available functions and types found in the retrieved context, rather than returning potentially hallucinated output.

#### Scenario: Both retries fail assertions
- **WHEN** the CoT output fails assertions
- **AND** the Predict output also fails assertions
- **THEN** the pipeline SHALL return an answer in the form: "I found information about {functions} but could not generate a verified answer. The available functions are: {list}."
- **AND** SHALL set `assertions_passed: false`
- **AND** SHALL set `used_fallback: true`

#### Scenario: Predict output passes assertions
- **WHEN** CoT output fails assertions
- **AND** Predict output passes assertions
- **THEN** the pipeline SHALL return the Predict output
- **AND** SHALL set `assertions_passed: true`
- **AND** SHALL set `used_fallback: true`

### Requirement: Assertion status SHALL be included in response metadata

The pipeline SHALL expose assertion results in the response dict, including which assertions failed and which retry stage produced the final answer.

#### Scenario: Assertion details in response
- **WHEN** a response is generated by any retry stage
- **THEN** the response dict SHALL include `assertions_passed` (bool)
- **AND** SHALL include `used_fallback` (bool) indicating whether the Predict path was used
