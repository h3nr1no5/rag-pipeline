## Context

The `fix-rag-query-freezing` change added 4 slow E2E tests in `tests/integration/test_rag_pipelines_e2e.py` that were meant to verify all RAG pipelines (cosine, LangChain, LlamaIndex, API-docs) end-to-end with real documents and no mocking. However, these tests are silently contaminated by the `seed_singletons` fixture in `tests/integration/conftest.py` (line 124-138), which is `autouse=True, scope="session"` and replaces real LLM/embedder instances with test doubles (`TestLLM` → returns fixed canned string, `TestEmbedder` → returns hash-based vectors).

The result: all 4 tests pass, but the answer is always the fixed `TestLLM` string `"This is a test response generated by the test LLM for testing purposes."` — it never contains actual document content. The assertion `len(result["answer"]) > 0` trivially passes.

Independently, the Streamlit frontend's `client/utils/query.py` silently returns `{"answer": "Please login to ask questions.", ...}` when the JWT token is missing from `st.session_state`, making auth failures invisible to the user (no error shown, just a fake answer).

### Current state

```
seed_singletons (session, autouse)
    │
    ├─ Real LLM  ──X── TestLLM        → "This is a test response..."
    ├─ Real Embedder ─X── TestEmbedder  → hash-based vectors
    │
    ▼
Test assertions: len(answer) > 0  ✅  (but answer is meaningless)
```

### Desired state

```
Slow E2E tests (marked @pytest.mark.slow)
    │
    ├─ RealisticTestLLM     → parses prompt, responds about document content
    ├─ TestEmbedder          → deterministic but functional
    │
    ▼
Test assertions: answer contains key terms from document  ✅  (meaningful)
```

## Goals / Non-Goals

**Goals:**
- Slow E2E tests verify the answer actually contains meaningful content about the uploaded document
- Eliminate `seed_singletons` contamination from `@pytest.mark.slow` E2E tests
- The `RealisticTestLLM` double extracts document content from the prompt and returns an answer about it, making the test verify both retrieval and LLM prompt coupling
- Frontend `client/utils/query.py` functions visibly signal auth failure instead of silently returning a fake answer
- All existing (non-slow) tests continue to work exactly as before with `TestLLM`/`TestEmbedder`

**Non-Goals:**
- Not changing the `TestEmbedder` — it already produces deterministic vectors that exercise the retrieval pipeline; the root issue is the LLM double, not the embedder
- Not loading real MLX or sentence-transformers models in tests — they are too slow (~500MB, segfault risks) and unnecessary for verifying RAG flow integrity
- Not changing the API response format or query endpoints
- Not changing the document processing pipeline behavior

## Decisions

### Decision 1: Create `RealisticTestLLM` for slow E2E tests

A new `RealisticTestLLM` test double that simulates realistic RAG behavior by inspecting the prompt for document source content:

- **How it works**: The prompt from `build_prompt()` has the structure `[Source 1]: <chunk_content>\n[Source 2]: <chunk_content>\n...\nQuestion: ...\nAnswer:`. `RealisticTestLLM.generate()` will parse the prompt for `Source N:` sections, extract text from them, and return a response that incorporates the first source's content.
- **Why not real MLX LLM**: Loading a real ~500MB MLX model in pytest is prohibitively slow (minutes), risky (PyTorch/MPS segfaults in asyncio), and not needed. The real retrieval → prompt assembly → LLM coupling is what we need to verify, and `RealisticTestLLM` does that.
- **What it verifies**: If retrieval finds no chunks (broken pipeline), the prompt will have no `Source N:` sections, and `RealisticTestLLM` will return a fallback string that the test can detect and reject.

```python
class RealisticTestLLM(LLM):
    """LLM double that responds with actual document content from the prompt.

    Parses prompt for ``[Source N]: ...`` sections and returns a response
    containing the text from the first source, simulating realistic RAG
    behavior without loading a real model.
    """

    def __init__(self):
        self._fallback = "I don't have enough information to answer this question."

    async def generate(self, prompt: str, ...) -> str:
        sources = _extract_source_texts(prompt)  # parses [Source N]: lines
        if not sources:
            return self._fallback
        return f"Based on the provided material: {sources[0][:200]}"

    async def generate_stream(self, prompt: str, ...) -> AsyncGenerator[str, None]:
        yield await self.generate(prompt, max_tokens, temperature)
```

### Decision 2: Override `seed_singletons` via module-level reseeding in E2E test file

Since `seed_singletons` is `autouse=True, scope="session"` and cannot be skipped per-test, the E2E test module will reseed the singletons with `RealisticTestLLM` **at module level** (before any fixtures run but after the session-scoped fixture has run):

```python
# In test_rag_pipelines_e2e.py, after module-level patches:
from tests.doubles.llm import RealisticTestLLM
import src.domain.services.llm as llm_mod
llm_mod._llm_instance = RealisticTestLLM()
```

This runs after `seed_singletons` has set `TestLLM`, replacing it with `RealisticTestLLM` for all tests in this module. The module-level patches that already exist (`_load_models = AsyncMock()`) prevent real models from loading during the lifespan, so `RealisticTestLLM` remains in place.

### Decision 3: Strengthen test assertions

Replace the weak `len(result["answer"]) > 0` in all 3 PDF-based tests with:

```python
# Verify answer IS NOT the generic canned response
assert result["answer"] != "This is a test response generated by the test LLM for testing purposes."
# Verify answer contains content about the document (RealisticTestLLM includes source text)
assert "material" in result["answer"].lower(), (
    f"Answer should reference document content, got: {result['answer'][:100]}"
)
```

The API docs test already has stronger assertions (checks sources, confidence, latency). Keep those and add the same content verification.

### Decision 4: Fix frontend silent auth failure

In `client/utils/query.py`, change the 4 `if not st.session_state.get("token"):` guards to return a distinct error dictionary that the chat page can detect:

```python
# Before:
if not st.session_state.get("token"):
    return {"answer": "Please login to ask questions.", "sources": [], "cached": False}

# After -- still friendly but with a detectable error flag:
if not st.session_state.get("token"):
    return {
        "answer": "Please login to ask questions.",
        "sources": [],
        "cached": False,
        "error": "not_authenticated",
    }
```

In `client/pages/3_💬_Chat.py`, add error handling after the concurrent dispatch to check for `"error" in result` and `st.error()` instead of rendering a fake answer.

## Risks / Trade-offs

- **[Risk] `RealisticTestLLM` is tightly coupled to `build_prompt()` output format**: If the prompt template changes (e.g., `Source N:` becomes `Document N:`) the double breaks. **Mitigation**: Add a unit test for `RealisticTestLLM` that verifies it correctly parses the current prompt format.
- **[Risk] Module-level reseeding is fragile**: If the test execution order changes or `seed_singletons` gets refactored, the reseeding might not work. **Mitigation**: Document the reseeding mechanism clearly. Consider moving slow tests to `tests/e2e/` directory with its own conftest if the reseeding pattern proves unreliable.
- **[Trade-off] TestEmbedder still used, not real sentence-transformers**: The embedding quality is deterministic/hash-based, so cosine similarity scores are not meaningful. **Mitigation**: The test verifies the end-to-end *flow* (upload → process → retrieve → prompt → LLM), not embedding quality. Embedding quality is tested in unit tests.
- **[Trade-off] No real MLX LLM in tests**: We lose coverage of actual LLM output quality, hallucination behavior, and token streaming. **Mitigation**: LLM quality is covered by the evaluation suite (`tests/evaluation/test_eval_rag.py`). The E2E tests cover pipeline integration, not model quality.
